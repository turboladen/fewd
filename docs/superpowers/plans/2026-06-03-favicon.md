# Favicon & Browser Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder 🍽️ emoji favicon with a custom place-setting icon set (SVG + ICO + apple-touch PNG) matching the app palette.

**Architecture:** Hand-author one canonical `favicon.svg` (sage squircle, gold plate ring, cream crossed fork & knife). A committed `scripts/gen-favicon.sh` rasterizes it — via `bunx sharp-cli` (no permanent deps) — and packs the lean `favicon.ico` (16+32 PNG-frame) with a committed `scripts/pack-ico.mjs` (run with `bun`; JS, no deps), plus a full-bleed-square `apple-touch-icon.png` (180). `index.html` references all three; the assets ship to the binary through the existing `bun run build` → `dist/` → `rust-embed` pipeline.

**Tech Stack:** SVG (hand-authored), `bunx sharp-cli` (libvips rasterizer), `scripts/pack-ico.mjs` (`bun` ICO packer — JS, no deps; replaces `bunx png-to-ico`, which bloated the .ico with an upscaled 256×256 frame), macOS `sips`/`file` for verification. Spec: `docs/superpowers/specs/2026-06-03-favicon-design.md`.

**Working directory note:** All commands assume the repo root (`/Users/sloveless/Development/projects/fewd`). Do **not** `cd server` — unrelated, but keep paths root-relative.

### Task 2: Write the asset-generation script

**Files:**

- Create: `scripts/gen-favicon.sh`

This script is the reproducible record of how the binary assets are produced. It rasterizes `public/favicon.svg` to the `.ico` frames, and derives a **square** (rx=0, full-bleed) variant for the apple-touch PNG so iOS can apply its own corner mask without double-rounding.

- [ ] **Step 1: Write the script**

Create `scripts/gen-favicon.sh` with exactly this content:

```bash
#!/usr/bin/env bash
# Regenerate favicon.ico and apple-touch-icon.png from public/favicon.svg.
# No permanent deps: bunx (sharp-cli rasterizer) + bun (ICO packing via pack-ico.mjs).
# Run from repo root:  ./scripts/gen-favicon.sh
set -euo pipefail
cd "$(dirname "$0")/.."

SVG="public/favicon.svg"
TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

# High density rasterizes the 100-unit viewBox crisply, then resize to target.
echo "→ rasterizing 16px / 32px PNG frames for the .ico"
bunx sharp-cli --density 600 -i "$SVG" -o "$TMP/favicon-16.png" resize 16 16
bunx sharp-cli --density 600 -i "$SVG" -o "$TMP/favicon-32.png" resize 32 32

# Pack a lean PNG-frame ICO (16 + 32). png-to-ico is avoided: it upscales to a
# fixed size ladder incl. a 256x256 frame (~270 KB, blurry). Our browser baseline
# (Safari 16.4+/Chrome 111+/FF 128+) supports PNG-compressed ICO frames, and the
# .ico is only a legacy fallback behind favicon.svg.
echo "→ packing favicon.ico (16 + 32)"
bun scripts/pack-ico.mjs "$TMP/favicon-16.png" "$TMP/favicon-32.png" public/favicon.ico

# apple-touch: square corners (rx=0), full-bleed sage — iOS masks its own rounding.
echo "→ deriving square apple-touch source"
grep -q 'rx="22"' "$SVG" || { echo "ERROR: rx=\"22\" not found in $SVG — cannot derive square apple-touch source" >&2; exit 1; }
sed 's/rx="22"/rx="0"/' "$SVG" > "$TMP/apple-touch.svg"

echo "→ rasterizing apple-touch-icon.png (180x180)"
bunx sharp-cli --density 600 -i "$TMP/apple-touch.svg" -o public/apple-touch-icon.png resize 180 180

echo "✓ done: public/favicon.ico, public/apple-touch-icon.png"
```

- [ ] **Step 2: Make it executable and commit**

```bash
chmod +x scripts/gen-favicon.sh
git add scripts/gen-favicon.sh
git commit -m "build(fewd-z0r): add gen-favicon.sh asset generator"
```

### Task 3: Generate and verify the binary assets

**Files:**

- Create (generated): `public/favicon.ico`, `public/apple-touch-icon.png`

- [ ] **Step 1: Run the generator**

Run: `./scripts/gen-favicon.sh`
Expected: the `→` progress lines, then `✓ done: ...`. Two files appear in `public/`.

> If `bunx sharp-cli` errors with "could not determine executable", use the explicit bin form everywhere in the script: `bunx --package sharp-cli sharp --density 600 -i ...`. Re-run.

- [ ] **Step 2: Verify the .ico is lean and has exactly both frames**

The JS packer emits PNG-frame ICOs, which `file` may report generically. Inspect the directory directly:

```bash
bun -e 'import {readFileSync} from "node:fs"; const d=readFileSync("public/favicon.ico"); const n=d.readUInt16LE(4); console.log("bytes",d.length,"frames",n); for(let i=0;i<n;i++){const o=6+i*16; console.log(`  ${d[o]||256}x${d[o+1]||256}`);}'
```

Expected: total bytes < 10000 (lean — png-to-ico used to bloat this to ~285 KB), `frames 2`, and sizes exactly `16x16` and `32x32`.

- [ ] **Step 3: Verify the apple-touch PNG dimensions**

Run: `sips -g pixelWidth -g pixelHeight public/apple-touch-icon.png`
Expected: `pixelWidth: 180` and `pixelHeight: 180`.

- [ ] **Step 4: Verify the apple-touch corners are filled (no transparency)**

The full-bleed requirement means the top-left corner pixel must be opaque sage, not transparent. Run:

```bash
bunx --yes sharp-cli -i public/apple-touch-icon.png --metadata 2>/dev/null | grep -i 'hasAlpha\|channels' || sips -g hasAlpha public/apple-touch-icon.png
```

Expected: either `hasAlpha: no` / `channels: 3`, OR if alpha channel exists, confirm visually in Step 5 that corners are sage (sharp may keep a 4th channel that's fully opaque — that's fine; what matters is corners aren't transparent).

- [ ] **Step 5: Eyeball both**

Run: `open public/favicon.ico public/apple-touch-icon.png`
Expected: `.ico` shows the squircle mark; apple-touch PNG shows the mark on a **square** sage field that runs edge-to-edge (corners are sage, not rounded/transparent).
